  POINTERS  
    
  הוא משתנה שמכיל כתובת בזיכרון (RAM). ניתן להצהיר על משתנה כזה עם סוג המשתנה \\\*שם המשתנה \=\> data\\\_type \\\*pointer\\\_name . נצהיר סוג משתנה בשביל שכשנשתמש בערך הכתוב בזיכרון נדע כמה BYTES רלוונטים למידע (בשביל לקבל את המידע הכתוב נשתמש ב \\\*).  
    
  בשביל להגיע לכתובת  בזיכרון של משתנה נשתמש ב \\& לפני הקריאה למשתנה.  
    
  גודל המשתנה POINTER הוא 4 bytes במערכות 32 bit ו 8 bytes במערכות של 64 bit.  
    
  סוגי pointer ים מיוחדים:  
    
  void: זה מצביע של מקושר לסוג משתנה ספציפי  
    
  wild: משתנה מצביע שהוצהר אבל לא שויך לכתובת ספציפית.  
    
  dangling: מצביע שהערך אליו הוא שויך נמחק או לא רלוונטי יותר לתוכנית. (יכול לקרות אם לדוגמא יש מצביע בפונקציה שמצביע על משתנה בפונקציה אחרת וכשהיא מסתיימת המצביע מתביע על משתנה שנמחק מהזיכרון). \- יכול לגרום לבאגים ולהתנהגות לא צפויה של התוכנית.  
    
  שימושים:  
    
  \* הוא יכול להיות שימושי לדוגמא בהעברת משתנים גדולים לפונקציה. ככה שבמקום שהנתון הגדול הזה ייכתב שוב בזיכרון התוכנית לתוך המחסנית תיכתב רק הכתובת בזיכרון.  
  \* במקרה שלא ידוע גודל של נתון מראש.  
  \* לעבודה על משתנים באופן גלובלי בתוכנית.

  **1.1**  
    
  **API-  application programming interface**

  הרעיון התיאורטי שבו מקשרים מספר תוכנות אחד לשנייה לשימושים שונים. (הישום של זה יכול להיות דרך DLL מה שמייחב ייבוא של קטע קוד מתוך ה הDLL לקוד השני או WebUSB API שמאפשר לתוכנות באינטרנט לגשת לרכיבי חומרה במחשב (כמו USB)).

    
  **WIN32API** 

  חבילת כלים, קבועים, מבני נתוניםופונקציות של WINDOWS שמאפשרת לתוכנות המשתמש לבצע פעולות תוך שימוש ביכולות שמוקצות למערכת הפעלה. כמו ניהול זיכרון, ניהול קבצים, ניהול רכיבי חומרה ועוד (כמו קלט משמשתמש).

    
  **ntdll.dll** \- הוא קובץ בתוך  USER MODE . הוא מכיל כלים שתוכנות אחרות יכולות להשתמש בהם עבור ניהול תהליכים, זיכרון ועוד.   והוא מתממשק ישירות עם כלים של מ"ה במרחב הקרנל.  
    
  **ring 0 and ring 3** \- 

  למ"ה יש מנגנון בטיחות כשזה נוגע להתממשקות עם רכיבי החומרה במחשב. כך למשל יש את הרעיון של טבעת שלישיתואפס. הרעיון שלמעבד יש מספר מצבי פעולה כשלכל אחד מהם יש הרשאות פעולה שונות. והם נקבעים על פי רגיסטר אחד בזיכרון שערכו בהתאמה לפעולות שהוא יכול לבצע.


  **SYSCALL** \- 

  פעולה שמתבצעת ב CPU בשביל להעיבר ת מצבו ל ring 0 ושידע לבצע את הפעולה שהגיע מהמשתמש.

    
  **סדר פעולות:**  
    
  \- קוראים ל  Win32 API function  
    
  \- הקריאה מועברת למקום המתאים בקובץ kernel32.dll שם הואט מכניס נתונים נוספים, ובודק את תקינות הבקשה ומעביר את הבקשה לקובץ NTDLL.DLL  
    
  \- ה NTDLL מכניס את הערך המספרי של SYSCALL המבוקש (לפי הטבלה System Service Descriptor Table (SSDT)) לרגיסטר מתאים ב CPU  
    
  \- מתבצעת קריאה ל SYSCALL במעבד. הוא מועבר למצב קרנל, השליטה יורדת מהאפליקציה, היא נעצרת. וקרנל מבצע את הSYSCALL המבוקש בהתאם למה שרשום ב רגיסטר ששונה מקודם ע"י ה NTDLL  
    
  \- לאחר שהקרנל מסיים לבצע את פעולות ה SYSCALL הוא מחזיר את המבוקש לתוכנית המשתמש בכך שהוא מכניס את השובה למרחב הזיכרון שלו.  
    
  \- מבצע SYSRET מה שמחזיר את השליטה לתוכנית המקור ובמקביל משנה את מצב המעבד ל ring 3\.  
    
    
    
    
    
  **1.2**  
    
  **ASCII VS UNICOD**  
    
  ASCII \- מייצג 128 תווים של השפה האנגלית, וסימנים מיוחדים  כאשר לכל סמל יש מספר בהתאמה לתו המתאים (טבלת אסקי). נדרשים 7 ביטים לייצוג כל תו.  
    
  UNICODE \- מספק תצוגה לכל תו בכל שפה מדוברת ואימוג'ים. נדרשים לפחות 8 ביטים לייצוג תו או 16 ביטים, (ב UTF8) יכול להגיע גם עד 34 ביטים לייצוג תו (UTF32).  
    
  מפני ש utf8  יכול להיות מוצג ע"י 8 ביטים, אז אפשר להגיד ש ASCII מוכל תחת UTF8 ו UNICODE בכללי.  
    
  ב C הברירת מחדל היא ASCII ולכן כשמגדירים char הוא מוגדר בגודל 1 byte בעוד UNICODE יכול להגיע 4 bytes. בשביל שהשפה תדע שאנחנו מתעסקים עם תווי UNICODE יש סימנים מיוחדים שנגדיר.  
    
  כך לדוגמא פונקציות מקבילות:  
    
  |char|wchar\\\_t (wide char : dinamic size), char8\\\_t, char16\\\_t, char32\\\_t|  
  |-|-|  
  |strlen()|wcslen()|  
  |printf()|wprintf()|  
  |None ("text")|u8, u, U, or L (L"text")|

  **TYPEDEF** \-  פונקציה לנתינת שם מקביל (אליאס) למבנה נתונים. דוגמא : typedef int number;  
    
  **IF DEFF** \- תנאי שבודק האם המזהה הוגדר כבר. (הרעיון של השמת ערך דומה ברעיון לCONSTאבל בפרקטיקה עובד כמו אליאס מסוג מחרוזת מכיוון שהוא כבר משנה בשלב של ה preproccessor את כל המזההים בערך).  
    
  שלב ה PREPROCCESOR מכין את הקוד לקימפול מבחינה שהוא בודק סינטקסט של פקודות, מוחק העות  ואנטרים ובשפת C הוא גם מבצע את ההחלפה הפרטית של מה שמוגדר כ DEFINE במהלך הקוד.  
    
  כפי שהוסבר השימוש בתנאי IF DEF ירוץ התנאי רק במידה והוגדר המזהה. היתרון בזה הוא שמפני שבשלב הזה כל מקום בו רשום המזהה בקוד הוא מוחלף בערך שהוגדר. גם התנאי רץ רק במקרה והמזהה הוגדר קודם לכן ובמידה שלא ה PREPROCESSOR ימחק את הקטע הזה מהקוד לפני הקימפול.  
    
  ומידה ונרצה להראות שאנחנו בסבית פיתוח נגדיר את המזהה וכך תהיה לנו גרסה של המפתחים .

  **1.6.2**  
    
  **macro** \- שם סימבולי.אליאס  לערך מסויים. הערך המסויים יכול להיות פונקציה, ערך מספרי, טקסט, או מצביע למקרו אחר.   הוא לא מתעסק בסוגי משתנים מפני שהוא מיוחס עוד לפני שלב הקימפול. הקומפיילר מקבל את הקוד לאחר שהוא כבר החליף את השם במהלך הקוד בערך.  
    
  ב c  ה MACRO הוא הערך שנשים בו את ערך החלופי ו DEFINE היא הפקודה (\#define LIMIT 100)LIMIT \= MACRO, פקודה \= define.  
    
  למה להשתמש?  
    
  \* אפשר לקוד לרוץ בצורה שונה בסביבות שונות כמו סביבת פיתוח או סביבת הפצה. (לדוגמא אם נבדוק ש win32 מוגדר נדע שהתוכנית מקומפלת בסביבת ווינדואז.  
  \* סוג המשתנה גמיש  
  \* בשימוש macro לצורך פונקציות אין קריאה לפונקציה או פעולות כאלה שלוקחות זמן אלא הפונקצייה מודבקת ממש במקום בו היא צריכה לרוץ בקטע הקוד (זה גם הוף את הקוד לכבד יותר \- חיסרון)  
  \* קוד קריא משמש כמו CONSTANTS
